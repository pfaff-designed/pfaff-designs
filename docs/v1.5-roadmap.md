# **Pfaff.design — v1.5 Roadmap**
*Stability → Clarity → Quality*

v1.5 has two strategic goals:

1. **Stabilize and unify the system** — front‑end, back‑end, AI runtime, knowledge retrieval, and component architecture.
2. **Improve the quality, depth, and reliability of AI output** — powered exclusively by `modalGraphApp` + the new Master Knowledge Base.

This release establishes a clean operational foundation before larger v2 features (adaptive layouts, dynamic pages, intelligent UI patterns).

---

# **PHASE 1 — System Audit & Stabilization**

This phase focuses on correctness, robustness, maintainability, and aligning all moving pieces into a single runtime.

---

## **1.1 AI Architecture Consolidation (modalGraph-only runtime)**

### **Description**
Retire the split-brain problem between modalGraph + copywriter/orchestrator. For v1.5, the AI system used by users will be **one unified pipeline**:

> **Live AI Runtime = modalGraphApp + Master KB + Supabase RAG**

The copywriter and orchestrator remain in the codebase as “offline generation tools” but are not used in the interactive runtime until v2.

### **Outcomes**
- One AI system to test, trace, and tune.
- Predictable behavior across the entire site.
- Eliminates prompt drift and conflicting behavior.
- Simplifies debugging, evaluation, and observability.

### **Instructions**
- Route all chat requests exclusively through `modalGraphApp`.
- Load modal prompts from LangSmith using `getModalGraphSystemPrompt`.
- Remove inline modal prompts.
- Connect modalGraph’s retrieval node to `retrieveProjectChunks`.
- Integrate Master KB slices (profile, project summaries, glossary).
- Suppress orchestrator/copywriter in all user-facing flows.

### **ETA (solo dev + AI assist)**
**4–6 hours**

---

## **1.2 Back-End Hardening**

### **Description**
Address issues found in the backend audit.

### **Outcomes**
- Stable RAG pipeline for modal.
- Reduced hallucinations.
- Better security and cost control.
- Visibility through proper tracing.

### **Instructions**
- Add auth + rate limits to `/api/ai/modal`, `/api/ai/query`, `/api/generate`.
- Replace long-lived signed URLs with server-generated short-lived URLs.
- Enable LangSmith tracing for modalGraphApp runs.
- Add structured error handling to Supabase RPC calls.
- Add groundedness heuristics (e.g., require retrieved chunks for non-portfolio queries).
- Implement a 30–60s cache for modal retrieval results.

### **ETA**
**3–5 hours**

---

## **1.3 Front-End Architecture Cleanup**

### **Description**
Address FE audit: remove the “god component,” improve maintainability, and eliminate brittle inline behavior.

### **Outcomes**
- Cleaner, testable UI.
- Reduced visual bugs.
- Predictable mobile behavior.

### **Instructions**
- Split `Composer.tsx` into:
  - `ComposerShell`
  - `ComposerInput`
  - `ComposerStatus`
  - Optional: `useComposerController`
- Move recurring inline styles into Tailwind utilities.
- Add focus trap for the AI modal.
- Reduce MediaImage HEAD checks to dev/debug.

### **ETA**
**4–6 hours**

---

## **1.4 Section Type Pruning & Schema Simplification**

### **Description**
The codebase currently defines more section types than the site uses. These complicate RAG, orchestrator mappings, and future refactors.

### **Outcomes**
- Clean, minimal schema.
- No unused types for LLMs to hallucinate.
- Stronger KB → UI alignment.

### **Instructions**
- Inventory all section types across:
  - Supabase schema
  - KB documents
  - Component registry
  - Orchestrator mappings
- Remove unused types entirely.
- Add a test to validate all referenced types are allowed.

### **ETA**
**2–4 hours**

---

## **1.5 Testing Layer Upgrade (FE + BE)**

### **Description**
Create the foundation of a predictable test suite.

### **Outcomes**
- Guardrails for regressions.

### **Instructions**

**3–5 hours**

# **PHASE 2 — Improve AI Output (Depth, Tone, Reliability)**

This phase ensures the AI feels intelligent, grounded, and recruiter-ready.

---

## **2.1 Integrate the Master KB (Global Unified Knowledge)**

### **Description**
Use the new unified KB as the backbone of every answer.

### **Outcomes**
- Deep, consistent answers.
- No page-level knowledge silos.
- Dramatic reduction in hallucinations.

### **Instructions**

  - tools
  - timelines
  - project types
  - visibility (public/hidden)
- Ensure modalGraph retrieves both:
  - project-specific chunks (if on a case study)
  - global slices (always)

**3–4 hours**
